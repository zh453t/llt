# llt-gui — 路路通时刻表查询

用 Rust + [egui](https://github.com/emilk/egui) 写的轻量桌面 GUI，直接读取
`out/timetable/llt-timetable.sqlite`（由 `cli/` 或 `tools/decode_llt.py` 解码路路通离线数据得到），
提供三种查询，并且三种查询都先选定一个**查询日期**：

| 标签页 | 功能 |
|---|---|
| **站站** | 输入出发站和到达站（出发框按 Enter 直接跳到到达框），列出可直达的车次、出发/到达时刻、历时、里程、跨天信息；「模糊」同样按同城组匹配，结果可按实际出发站/到达站筛选。输入即查询，「刷新」只是兜底（小按钮，正常不用按）。排在第一位，也是第一次启动的默认页。 |
| **车次** | 输入车次（`G1`、`K54`、`1461`、`G100/G97`），支持前缀匹配；也支持只输入车次号（`54` → `G54` / `K54` / `Z54`）。 |
| **车站** | 输入站名或城市名，实时给出候选站；勾选「模糊」后按同城组匹配全部车站，可用「车站筛选」勾选子集。 |

日期选择器默认是今天；只有切换到其他日期时，旁边才会出现“今天”按钮，可一键回到当天。
窗口足够宽时日期控件与标签页同排，窄窗口（< 620 点）时自动独占一行，避免标签与日期被换行拆散。查询结果合并到
**同一个滚动列表**：当日开行的车次排在前，不开行的车次紧随其后；列表上方显示两组趟数，
每行左侧的 `●` / `○` 分别表示当日开行 / 不开行。

- 车次页：判断所选日期是否落在该车次的始发开行区间内。
- 车站页：根据停站的“第几天”倒推出始发日期，因此夜间车和跨天车按“当日在本站有车”归类。
- 站站查询：根据出发站的“第几天”倒推始发日期，按“当日能从出发站乘车”归类。
- **模糊（同城）**：勾选后用 `same_city_groups` / `same_city_members` 把输入解析成同城组，
  城市名节点（如成都）和车站名（如北京、北京南）都能匹配；镜像组（天津 / 滨海）取并集，
  标题用成员最多的组名。未勾选时仍是精确站名。
  车站页的「车站筛选」按站点勾选子集（全选 / 全不选），站站查询的「车站筛选」按结果里实际
  出现的出发站 / 到达站过滤，并新增「区段」列显示 `北京南 → 上海虹桥` 这样的实际乘降区间
  （悬停显示全程）。筛选都是 chips，一次点击生效；站站的「出发」「到达」各占一行、
  不再带「筛选」二字；旧库没有同城表时自动退化为单站查询。
  站站筛选两侧互为约束：选定出发站后，没有对应直达车次的到达站 chip 会被禁用（反向同理），
  与另一侧不兼容的旧选择会自动清除，筛不出空列表。

任意查询结果中点击一行，**详情区**会展开该车次的完整信息（车次号使用粗体）：

- **用时**：首站发车到末站到达的运行时数（如 `4小时54分`）；跨天时补 `(2天)`，
  例如 `59小时19分 (3天)`，小时数不折回 24 以内。
- **交路**：车底周转顺序（如 `G1806/7 → G82/79 → G32 → [G1] → G1956/7`），
  高亮的一段是当前车次；同号多区间时按查询日期过滤，当天没有有效交路才显示全部并提示。
  其余车次是深蓝色链接，点一下就地换成那趟车的详情——交路本身就能来回走，
  跳过去以后在同一条交路上点回来即可；`0` 开头的回送车和 `DJ` 检测车没有独立时刻表，
  保持灰色不可点（悬停说明原因）。左侧列表不受影响，用户原来的查询结果还在。
- **车型**：交路里的编组（如 `CR400BF-S型重联`），数据缺失时退回车次类别。
- **担当**：担当企业（如 `上局上海段`）；有餐车时附餐车车厢。
- **经由**：宽屏侧栏里是默认收起的折叠项，标题（粗体「经由」+ 点数/里程/车站数）与
  停站表同级；窄屏时改为停站表下方的一行「经由 · 点数 · 里程 · 查看」入口，点开后在独立
  整页里显示同样的内容（顶部「返回」，点遮罩或按 Esc 也能关闭）。宽屏展开后，经由表直接
  吃掉侧栏下方的全部高度（停站表暂时让位，收起经由即恢复）——两边各分一半时都只剩两三行，
  反而谁都看不清；图例行右侧还有一个「放大」按钮，打开封顶 760×82% 的居中弹窗，
  方便看很长的经由；表格是三列
  `站点 | 线路 | 里程`，字号与行高和停站表一致，并带「只看车站」过滤与图例：

  | 颜色 | 含义 |
  |---|---|
  | 蓝色站名 | 该站是本车次的办客停站 |
  | 橙色线路名 | 由此换到另一条线路（跨线站显示为 `京包张包段/包西线`） |
  | 灰色斜体（图例「非办客」） | 不办理客运的点：线路所、信号所、未收录的货运站等，勾选「只看车站」后隐藏 |

  换线判定按线路名拆分比较：`A → A/B` 标在共用站，`A/B → B` 不会重复标。
- **停站表**：到发时刻、里程、第几天；悬停站名可看停留时间。跨日处（「第 N 天」变化）
  会画一条分隔线，夜车一眼能看出换天位置。站名是深蓝色链接（悬停出现下划线 + 手型光标），
  点一下切到「按车站查询」并只查这一站。**只有站名字形是点击入口**，命中外扩 2×4 点，
  点时间 / 里程 / 天数或行内空白都不会跳走；窄屏先收起底部详情——它要占掉大半高度，
  留着会把新的车站表压得只剩两三行。链接色与「选中行文字 / 聚焦描边」是同一支深蓝，
  同一界面不会出现两种蓝。
- **回头路分两维，各说各的**：跳车站后，车站页顶部出现「← 天津」（原来不在车站页时
  写上一页的名字，如「← 按车次」），点一下回到上一处并恢复原来的车站查询与详情；
  换车次后，详情标题栏「关闭」左边出现「← G105」。两个入口都不混用另一维的名字——
  在车站页看到车次号会让人以为要跳去那趟车。

旧库（`tools/decode_llt.py` 生成）没有经由 / 交路表，这几行会自动隐藏，只显示停站表。

宽屏时详情为右侧边栏（默认约占窗口宽度的 36%，380–560 点，可拖动）；
窗口窄于 820 点时自动改为底部详情面板，并切换成左右分栏（左边车次信息，右边停站表；
经由入口固定在停站表下方），避免把停站表挤得不可用；窗口再窄于约 580 点时，底部面板改为
上下排列——信息区按内容收缩（最多占 45%）并可滚动，停站表占满剩余高度，经由入口仍在
表格下方。点“关闭”即可收起；点经由入口打开整页，页面覆盖内容区并压暗背景；宽屏侧栏
展开经由后整块占满下方空间，另一个入口是用「放大」打开封顶的居中弹窗。

标签页会写进 `llt-gui.json` 的 `ui.tab`，下次启动回到上次那一页（第一次启动是站站）；
查询日期不落盘，每次启动都是今天。宽屏（窗口 ≥ 820 点）下输入框自动接管焦点：启动就落在
恢复出来的那一页的输入框，切标签页落到该页的输入框（站站优先落在还空着的那一侧），
点「清空」后焦点留在原处，可以直接接着打字。
只在启动 / 切页 / 清空这三个时刻抢一次，不逐帧抢占，所以点复选框、日期控件、筛选
chips 时不会被弹回输入框；窄屏不接管——小窗口常对应触屏，弹出行内键盘比省一次点击更烦。
再点一次当前标签页，等于把焦点重新交给该页输入框。

站站查询还多一条：在**出发框按 Enter** 直接把焦点交给到达框（单行输入框按 Enter 本来
就会失焦，这里顺手接管）。这一条不看窗口宽度——键盘此时已经在这个输入框上，跳一格不会
额外弹出行内键盘；光标落在到达框末尾，和切页 / 清空一致，不额外做全选。

表格按自身可用宽度隐藏次要列：车次表的类型 / 里程 / 天数，以及很窄时的开行日期
（日期改在车次单元格的悬停提示里）；车站表的停留 / 第几天 / 类型 / 本站里程，极窄时再收起
「始发 → 终到」（路线改在车次悬停提示里）；站站表的里程 / 类型 / 全程，极窄时收起「历时」
（改在车次悬停提示里）。窄列中的站名和线路用省略号截断，悬停可看全文。

## 构建与运行

在仓库根目录（workspace）执行：

```bash
cargo run -p llt-gui --release
```

也可以在 `gui/` 目录里直接 `cargo run --release`。生成的可执行文件在
`target/release/llt-gui.exe`（Windows 下不会弹出控制台窗口）。
默认窗口大小为 1600×1000，首次显示时会按屏幕可用大小收敛一次。

### 指定数据库

按以下顺序解析数据库路径：

1. 命令行：`llt-gui --db <path>` 或 `llt-gui --db=<path>`
2. 环境变量：`LLT_DB=<path>`
3. 常见相对位置：`out/timetable/llt-timetable.sqlite`、
   `../out/timetable/llt-timetable.sqlite`、可执行文件附近的同名文件，以及
   `target/{debug,release}/../../../out/timetable/llt-timetable.sqlite`

数据库只以只读方式打开，不会修改原始数据。

### 指定配置文件
界面状态（标签页、三组查询词、两个「模糊」开关、经由「只看车站」）写在可执行文件旁的
`llt-gui.json`，路径按以下顺序解析：

1. 命令行：`llt-gui --config <path>` 或 `llt-gui --config=<path>`
2. 环境变量：`LLT_CONFIG=<path>`
3. 可执行文件旁：`llt-gui.json`（绿色版，和数据库放同一个目录即可）

停止输入 0.5 秒后落盘（先写 `.tmp` 再改名覆盖），关窗时再兜底一次；配置缺失或损坏不会
阻断启动——缺失按默认值、损坏回退默认值并把原文件改名 `llt-gui.json.bad`。
字段与方案详见 [`../docs/gui-config.md`](../docs/gui-config.md)。

### Android

同一个界面也能装成 APK（`android/` 是独立的 cdylib 包，复用本目录的 `llt_gui` 库）：

```powershell
pwsh -File android/build.ps1 -Release   # -> android/target/release/apk/llt-gui.apk
```

Android 上没有「可执行文件旁」这个概念：数据库随 APK 下发，首次启动解到应用私有目录
`/data/user/0/org.llt.timetable/files/`，配置文件 `llt-gui.json` 也在那里，
`--db` / `--config` / `LLT_DB` / `LLT_CONFIG` 这些入口在 Android 上不参与。
中文字体取自系统 `/system/fonts`；状态栏、导航栏与软键盘的位置由应用自己让开。
系统输入法另有一条通道：`run_with` 的 `ime` 参数由平台侧实现 `ImeBridge`
（桌面传 `None`，走 egui-winit），界面每帧把上屏 / 合成 / 删除事件转成 `egui::Event`
推给输入框——Android 的 `NativeActivity` 没有 `InputConnection`，不接这一层中文进不来。
完整方案、环境要求与已知限制见 [`../docs/android.md`](../docs/android.md)。

## 数据

表结构见 [`../out/timetable/README.md`](../out/timetable/README.md)。当前数据版本
20261108：14,889 趟车、3,331 个车站、141,910 条停站。

GUI 读 `trains`、`stops`、`stations` 三张主表；交路 / 车型 / 餐车 / 经由来自
`duties`、`duty_segments`、`duty_trains`、`dining_cars`、`train_routes` 等附加表
（`llt build` 写入，表缺失时相关行自动隐藏）。标题栏的「数据 2026-11-08」则来自
`llt build` 写入的 `meta.data_version`（缺失时退回 `PRAGMA user_version`）；
由解码脚本重新生成、没有版本信息的 `llt-timetable.sqlite` 也能直接使用，只是不显示该日期。

## 实现要点

- `gui` 既是库（`llt_gui`）也是桌面可执行文件：库里是界面、配置、字体、主题与
  `run_with()` 启动函数，`main.rs` 只解析 `--db` / `--config` 然后调库。Android 入口
  （`android/`）复用同一个库，数据库与配置路径由它给（应用私有目录）。
- `eframe`/`egui` 0.37（使用默认 features 和默认的 wgpu 渲染后端），
  `egui_extras` 虚拟化表格：上千行车站时刻表也只绘制可见行。
- wgpu 设备上限取适配器自己上报的值（`adapter.limits()`），而不是 wgpu 的默认上限：
  部分后端的默认值偏高（模拟器的 SwiftShader Vulkan 只给 16 KiB 的 uniform buffer）。
- 系统栏缩进（状态栏 / 导航栏 / 软键盘 / 刘海）由 `ScreenInsets` 描述，桌面恒为 0；
  Android 传回调，界面最多每 150 ms 问一次，根 `Ui` 的矩形随之缩进。
- 「数据」页（`gui/src/data.rs`）在两端共用：检查更新、下载重建、备份导入导出。
  耗时动作在后台线程里跑，结果用 channel 回传；Android 的导入导出由
  `files::FilePicker` 转给系统的文件选择器，桌面直接读写可执行文件旁的目录。
- `rusqlite` + bundled SQLite，单文件可执行，无需系统安装 SQLite。
- 中文字体：正文依赖 eframe 默认自带的 `system_fonts`，缺字时按需从系统中文字体回退；
  需要真正加粗的文字（应用标题、车次号、表头、终到站）额外加载
  `msyhbd.ttc` / `Dengb.ttf` / Noto Sans CJK Bold，注册为独立的粗体字族
  （`RichText::strong()` 只改颜色，不等于粗体）。
- 平台差异只有一个入口：`Platform { insets, ime, pointer }`（`src/lib.rs`）。桌面与
  Android 走同一套界面，差别只在安全区、输入法通道与指针类型三个字段上。
- 触摸屏上列车详情是**整页**（替换列表，标题栏右侧是「返回」），桌面窄窗仍是底部面板；
  触摸屏还关掉 `selectable_labels`，否则 `Label` 的 click sense 会吃掉「点行打开详情」。
- 控件高度、列表行高、详情行高、可点文字热区、滚动条宽度都随 `theme::pointer()` 取值：
  鼠标 30 / 28 / 26，触摸屏 44 / 42 / 38。宽度阈值同样集中在 `theme`（`WIDE_MIN_WIDTH`、
  `STACKED_DETAIL_MAX_WIDTH` 及各表的列阈值），界面里不写字面量。
- 字号、行高、控件高度、间距和浅色/深色配色集中在 `src/theme.rs`：
  正文 15、辅助信息 13、标题 17/20、车次号 24，输入框与按钮统一 30 点高，
  表格表头 30 / 列表行 28、详情表头与行 26，所有区域共用同一套颜色与圆角。
- 详情里的表格表头有细分隔线，列表表头也有同样的下边框；选中行使用低饱和浅蓝底，
  选中文字用深蓝而不是强调色本身，避免整行变成蓝色。
- 表格里任何单元格的内容都不许宽于列宽。`egui_extras` 的选中/斑马底是按“列宽与内容
  宽度取并集”逐格铺的：内容一旦撑破列宽，该格占位越界、后面几列整体右移，于是同一张表
  里“跨日的行排版不一样”，选中行底色还会被越界撑出的缝隙切成几段。跨日时刻因此拆成
  两段——等宽时间 + 小一号弱化的 `+N天`；历时列则限制最小值并用省略号兜底。
  后缀的基准日各表不同：车站表说“这趟车从始发算起第几天”（与「第几天」列同义），
  站站查询的**出发列不带后缀**（出发日期就是查询日期），只有到达列标“次日到 / +N天到”，
  基准是上车日期，正好和「历时」对得上。
- 车次/车站查询在 14k 车次、14 万停站的数据量下都是毫秒级；停站关联查询走
  `stops_station` / `stops_train` 索引，交路走 `duty_trains.train_index` 索引。
- 站站查询使用 `stops s1 JOIN stops s2 ON s1.train_index = s2.train_index AND s1.seq < s2.seq`，
  按出发时间排序，结果上限 500 条。
- 日期选择使用 `egui_extras` 的 `DatePickerButton`（`datepicker` feature，底层是 `jiff`）。
  查询日期只影响开行标记，切换日期不会重新查库，只重新排序并更新每行的状态。
  弹层关闭了默认的红色周末高亮和 ISO 周数列，其余外观由 `theme.rs` 统一。
- 三种查询的结果最终合并成一个虚拟化表格：开行在前、不开行在后，共用同一个滚动区域；
  开行与不开行的交界处有分隔线，不会再把两组固定分配到上下两块区域。
- 车次查询不截断结果，保证“当日开行 / 不开行”的计数完整；表格本身是虚拟化的，
  几千条结果也只绘制可见行。
- 详情面板按可用宽度分档：宽侧栏显示完整信息，窗口窄于 820 点时改为底部面板的
  左右分栏（左边信息、右边停站表），再窄于约 580 点时改为上下排列；
  信息区按内容收缩、最多占 45%，内容超长时自己滚动，把高度留给停站表。
- 窄屏的经由不内嵌：停站表下方保留一行入口，点开后用整页 Modal 显示经由，
  背景压暗、拦截下层输入，返回 / 点遮罩 / Esc 关闭，避免只有两三行的挤迫视图。
  宽屏侧栏仍保留默认收起的折叠项，展开后可用「放大」打开封顶 760×82% 的居中弹窗；
  折叠表格、弹窗和整页表格的高度都按整行取整。窗口尺寸变化时经由页/弹窗会自动关闭，
  回到详情，重新打开即按新尺寸排布。
- 过渡时长统一改成 0.13 秒（egui 默认 0.2 秒），只影响 egui 内建的几处：弹窗/整页淡入、
  滚动条淡入淡出、折叠箭头与面板开合。界面本身不做自定义动画——表格是密集扫视型，
  布局动画还会和“高度按整行取整”打架。
- 首次显示时按屏幕大小收敛一次窗口，兼容高 DPI / 远程桌面下窗口超出屏幕的情况。

## 已知限制

- 站站查询只找**直达**车次，不计算中转换乘。
- `trains.date_from` / `date_to` 是数据里的连续开行区间；若某车次还有周内停运、
  临时调整等更细的开行规律，当前数据没有提供，界面无法判断。
- 同一车次号可能对应多个开行区间（如 `K54` 老区间与 `G54`），列表会全部展示。
- 日期选择弹层由 `egui_extras` 提供，月份、星期和“Cancel / Save”仍为英文；
  本应用只关闭了红色周末高亮和周数列，没有替换整套弹层。
